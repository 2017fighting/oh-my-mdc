# 原型：向导与面板（throwaway）

> **这不是产品代码。** 回答 [#11](https://github.com/2017fighting/oh-my-mdc/issues/11) 的问题：设置向导和任务面板到底长什么样。三个结构上完全不同的变体，用来挑、用来拼，不直接进 main。所有数据都是写死的假数据，所有「测试连接」都是 900ms 后假装成功。

## 跑起来

```bash
pnpm --dir prototype/ui install   # 首次
pnpm --dir prototype/ui dev       # http://127.0.0.1:5273
```

底部悬浮条切换变体（或按 ← →）；「向导 / 面板」切换两个界面；「未初始化」模拟全新安装（三件套未配齐，只有向导，面板被挡住）。

## 三个变体

| 变体 | 向导 | 面板 | 再配置入口 |
|---|---|---|---|
| **A** 分步向导 + 表格面板 | 左侧步骤条，一屏一步，每步独立「保存本步」；qB 步骤内嵌 autorun 前后对比 | 四张统计卡 + 「需要人工」告警区 + 稠密任务表，点行开右侧抽屉（版本 + 事件时间线 + 重试/强制重刮） | 侧边栏「集成设置」回到同一个向导 |
| **B** 单页卡片 + 看板 | 没有步骤：六张集成卡片一页铺开，卡片各自保存（对应 #8 的按表 PATCH）；可选项带开关；顶部粘性「三件套 3/3」进度头 | 任务状态四列看板（下载中/加工中/已入库/需人工），失败原因直接贴在卡片上，点开居中对话框 | 顶栏「设置」回到同一页卡片 |
| **C** 控制台 · 事件优先 | 单列编号区块（01 javdb…），等宽字体、test/save 小按钮，粘性进度条「三件套 x/3」 | 事件流（task_event）当首页主体，右侧窄栏是稠密队列 + 副作用待办，深色控制台皮肤 | 左侧图标栏「集成」回到同一列区块 |

## 已经按已决事项写死的东西

- 状态机：任务按 movie_id 聚合、版本按 infohash（#7）；状态 downloading / processing / finished / failed(phase, reason)。
- 设置按表 PATCH、敏感字段只吐掩码、每步/每卡一个「测试连接」写 last_test_*（#8）。
- qB 步骤展示 autorun 改写前后对比、回调走集群内 svc DNS、固定 category + 显式 savepath（#9）。
- 清单按 id 登记（#7），新建清单是「探测 + 手动兜底」的候选接口（#15）。
- 「未初始化」门：三件套不齐只给向导（#8）。
- 副作用队列（删清单项 / 刷 Jellyfin / 发通知）与 task_event 流水在面板上可见（#7/#8）。

## 想要的反应

1. 选一个变体，或者说「B 的卡片 + A 的表格」这类拼法。
2. 面板上最想一眼看到什么？（失败/停滞 vs 全队列 vs 事件流）
3. 向导里「一屏一步」vs「一页全铺」哪个更贴你的使用习惯（你会反复回来改设置吗？）。
4. 文案：状态名、按钮名、告警文案有没有要改的（会直接进 spec 的 UI 章节）。
